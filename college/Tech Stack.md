## FastAPI

**Что это:** Современный Python веб-фреймворк с нативным async.

**Почему FastAPI, не Django:**

| Критерий | FastAPI | Django |
|---|---|---|
| Async из коробки | Да, нативный | Через ASGI, ограниченно |
| Вес для микросервиса | Лёгкий | Избыточный |
| ORM, Admin, Auth | Не нужны нам | Есть, но нам не нужно |
| Старт контейнера | < 1 сек | 3–5 сек |
| Pydantic интеграция | Нативная | Отдельно |

**Роль в проекте:** Только точка входа и `/health` эндпоинт для Docker healthcheck. Основная работа — asyncio event loop, не HTTP запросы.

**Почему не чистый asyncio без фреймворка:** FastAPI даёт `/health`, `/docs` и удобный lifecycle для DI сборки при старте.

## Python asyncio

**Что это:** Встроенная в Python библиотека для конкурентного ввода-вывода.

**Почему:** Сервисы работают в event-driven режиме — подписались, ждут событий, обрабатывают. Это идеальный кейс для asyncio. Синхронный код заблокировал бы ожидание на MQTT и SDK одновременно.

**Где используется:**
- Одновременная подписка на несколько MQTT топиков
- Параллельная отправка команд нескольким LED экранам
- Heartbeat камер без блокировки основного цикла

## EMQX (MQTT Broker)

**Что это:** Высоконагруженный MQTT брокер, open-source.

**Почему MQTT, не REST/HTTP:**

| | MQTT | HTTP REST |
|---|---|---|
| Паттерн | Pub/Sub | Request/Response |
| Для event-driven | Идеально | Неудобно (polling) |
| Нагрузка 300 камер | Держит легко | 300 постоянных HTTP соединений |
| Один publisher → много подписчиков | Нативно | Сложно |
| Уже в проекте | Да (EMQX в docker-compose) | — |


## Redis

**Что это:** In-memory хранилище данных с поддержкой атомарных операций.

**Почему Redis для состояния мест:**

| Требование                            | Решение Redis                            |
| ------------------------------------- | ---------------------------------------- |
| 1800 мест, частые обновления          | In-memory: микросекунды на чтение/запись |
| Атомарный счётчик зоны                | INCR/DECR — атомарны по природе Redis    |
| Восстановление после рестарта         | AOF/RDB персистентность                  |
| Разделяемое состояние между сервисами | Один Redis, оба сервиса читают           |
| TTL для heartbeat камер               | Встроенный EXPIRE                        |

**Почему не PostgreSQL:** Реляционная БД избыточна для быстро меняющегося состояния. 300 камер × 6 мест = до 1800 обновлений в пачке — Redis справляется без нагрузки, PostgreSQL начнёт тормозить.

**Почему не in-memory в сервисе:** При рестарте сервиса состояние потеряется. Redis — общий источник истины.

## UNV OpenNetSDK / ONVIF

**Что это:**
- **UNV OpenNetSDK** — проприетарный SDK от Uniview для работы с их камерами
- **ONVIF** — открытый стандарт для IP камер видеонаблюдения

---


**Переменные окружения управляют режимом:**

| Переменная | Симуляция | Прод |
|---|---|---|
| `CAMERA_DRIVER` | `mock` | `unv_sdk` или `onvif` |
| `LED_DRIVER` | `mock` | `dahua` или `tcp` |
| `MQTT_BROKER` | `emqx` | `emqx` (одинаково) |
| `REDIS_URL` | `redis://redis:6379` | `redis://redis:6379` (одинаково) |
